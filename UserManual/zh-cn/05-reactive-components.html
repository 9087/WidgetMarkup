5. Reactive Python Components

Use @reactive, @computed, declarative property binding, and event delegates to build self-contained view-models. Prefer declarations over imperative code — data binding and event binding should be your first choice.

5.1 The base class

WidgetMarkupComponent is the only base class your component needs to extend. It provides:

  • create(module_name) — the factory the C++ side calls.
  • prime_computed_dependencies() — eagerly evaluates every @computed property so its dependency graph is ready.
  • on_property_changed(name, value) — override this to forward changes to the bound widget.

5.2 @reactive properties

Decorate a method whose return value is the per-instance default. The decorator turns it into a settable descriptor that emits a change notification whenever the new value differs from the old: 

from WidgetMarkupComponent import WidgetMarkupComponent, reactive


class Counter(WidgetMarkupComponent):
    @reactive
    def value(self):
        return 0

c = Counter()
c.value = 1   # triggers on_property_changed('value', 1)
c.value = 1   # no notification: equal to the previous value

5.3 @computed properties

Decorate a method that derives its result from other reactive (or computed) properties. Dependencies are collected at runtime on every evaluation, so conditional branches are handled correctly: 

from WidgetMarkupComponent import WidgetMarkupComponent, reactive, computed


class Picker(WidgetMarkupComponent):
    @reactive
    def left(self):  return 0
    @reactive
    def right(self): return 0
    @reactive
    def use_left(self): return True

    @computed
    def selected(self):
        return self.left if self.use_left else self.right

After use_left flips to False, only changes to right will recompute selected; changes to left are ignored until use_left flips back. Computed properties are read-only.

If a computed property is never read before its dependencies change, it cannot announce its update because no dependency graph exists yet. Call self.prime_computed_dependencies() at the end of __init__ to build the graph eagerly.

5.4 Cycles and re-entrancy

  • Cyclic computed dependencies raise RuntimeError at evaluation time. The error message contains the offending path, for example first -> second -> first.
  • Inside on_property_changed you may write to other reactive properties; the resulting notifications are flushed before the original write returns.
  • If a computed function raises while recomputing, the cached value stays untouched and the next read attempts to recompute again.

5.5 Observable lists

Any plain Python list assigned to a @reactive property is automatically wrapped in an ObservableCollection. In-place mutations (append, extend, insert, pop, remove, clear, sort, reverse, slice assignment, and +=/*=) trigger a change notification: 

from WidgetMarkupComponent import WidgetMarkupComponent, reactive, computed


class Inventory(WidgetMarkupComponent):
    @reactive
    def items(self):
        return []

    @computed
    def item_count(self):
        return len(self.items)

inv = Inventory()
inv.prime_computed_dependencies()
inv.items.append('Sword')   # notifies 'items' and 'item_count'

5.6 Property binding in XML

Bind a widget property to a @reactive or @computed Python property directly in XML using {propertyName} syntax: 

<TextBlock Text="{display_value}" Font.Size="18" />
<ProgressBar Percent="{progress}" />
<CheckBox IsChecked="{enabled}" />

When self.display_value = "new" is assigned in Python, the TextBlock updates automatically — no manual widget lookup or set_text() calls required. The binding name must match the @reactive property name exactly.

Design principle: Always prefer {property} data binding over manual find_widget + setter calls. Manual widget manipulation is a last resort, not the default pattern.

5.7 Event binding

Connect widget events to Python handler methods with OnClicked="method_name" or OnMouseButtonDownEvent="method_name": 

<!-- Button click -->
<Button OnClicked="on_confirm">
  <TextBlock Text="Confirm" />
</Button>

<!-- Mouse button on Border (supports left/right distinction) -->
<Border OnMouseButtonDownEvent="on_cell_click"
        BrushColor="0.72,0.72,0.74,1">
  <TextBlock Text="{label}" Visibility="HitTestInvisible" />
</Border>

Python handler signatures:

def on_confirm(self):
    self.status = "Confirmed"

def on_cell_click(self, geometry: unreal.Geometry, mouse_event: unreal.PointerEvent):
    ...
    return unreal.WidgetLibrary.handled()

5.8 Pointer events and InputLibrary

UE's FPointerEvent::EffectingButton is not exposed to Python reflection. WidgetMarkup provides widget_markup.InputLibrary (backed by UWidgetMarkupInputLibrary with UPARAM(ref)) to read button state correctly: 

import widget_markup

def on_mouse_down(self, geometry, mouse_event):
    key = widget_markup.InputLibrary.pointer_event_get_effecting_button(mouse_event)
    if key == widget_markup.Key.RightMouseButton:
        self.flag()
    elif key == widget_markup.Key.LeftMouseButton:
        self.reveal()
    return unreal.WidgetLibrary.handled()

widget_markup.Key provides EKeys constants (e.g. LeftMouseButton, RightMouseButton). Do NOT use mouse_event.effecting_button or mouse_event.get_editor_property() — they return None.

5.9 Dynamic child widgets

Create and remove child widgets at runtime with add_child and remove_child: 

# Create a WidgetMarkup child blueprint dynamically
cell = self.add_child("Cell_0_0", "/WidgetMarkup/Samples/MinesweeperCell", parent_panel)

# Register a click callback on the child
cell.on_click = lambda geo, evt: self._handle_click(geo, evt)

# Remove by name or reference
self.remove_child("Cell_0_0")

add_child(name, class_token, parent) compiles the blueprint on demand (if not already cached), creates the widget, adds it to the parent panel, and returns the WidgetMarkupComponent (or None for plain UMG widgets).

5.10 Design principles

Follow these priorities when building WidgetMarkup components:

  1. Data binding ({reactive} / {computed}) — push data to widgets declaratively.
  2. Event binding (OnClicked="handler" / OnMouseButtonDownEvent) — react to user input through the XML delegate system.
  3. Manual widget access (find_widget + setter) — only when binding cannot express the behavior.

Minimize coupling between components. Use @computed to derive visuals from local @reactive state instead of reaching into parent components. Route child-to-parent communication through callback registration (e.g. cell.on_click = lambda ...) rather than direct parent method calls. Cross-instance dependencies are not auto-tracked by the reactive system — keep them explicit and minimal.
